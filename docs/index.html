使用文档

适用于 Roamtty Android 版与 iOS 版。找不到答案？请看支持页面或发邮件至 support@roamtty.com。

Roamtty 是 SSH 客户端：AI 编程工具（Claude Code、Codex、Grok 等）运行在你自己的服务器上，Roamtty 在手机上启动它们、显示它们的状态，并让你在触屏上顺手地操作终端。应用本身不带模型，也没有后端服务器，连接只发往你添加的主机。

快速开始

  1. 准备一台能 SSH 登录的服务器，在上面装好并登录你要用的 AI 命令行工具。见准备服务器。
  2. 让手机能访问到它。同一 Wi-Fi 下可直接用局域网地址；在外面用蜂窝网络时，推荐用 Tailscale 组网，服务器不必暴露在公网。
  3. 在 Roamtty 的主机页点 + 添加主机，首次连接核对指纹后，在主机菜单中选“安装插件”装上 tmux 和 mosh。
  4. 点“AI Agent”，选 Agent、主机和起始文件夹，开始工作。锁屏、断网或关掉应用后，任务仍在服务器上的 tmux 里运行，回来时自动接上。

准备服务器

任何能通过 SSH 登录的 Linux、macOS、BSD 或 Windows 主机都可以，例如家里的台式机、公司的开发机、云服务器或 Mac。

开启 SSH 服务

系统做法
Ubuntu / Debiansudo apt install openssh-server，然后 sudo systemctl enable --now ssh
Fedora / RHELsudo dnf install openssh-server，然后 sudo systemctl enable --now sshd
macOS系统设置 → 通用 → 共享 → 打开“远程登录”
Windows 10/11设置 → 系统 → 可选功能 → 添加“OpenSSH 服务器”；在管理员 PowerShell 中运行 Start-Service sshd; Set-Service sshd -StartupType Automatic

安装 AI 命令行工具

在服务器上按各工具的官方说明安装 Claude Code、Codex 或 Grok 的命令行版本，并先在服务器上登录一次（完成账号或 API Key 配置）。Roamtty 只负责在你选的文件夹里启动它们，不会替你登录，也不会经手你的 API Key。确认在普通 SSH 终端里输入 claude、codex 或 grok 能正常启动即可。

tmux 与 mosh（推荐）

  • tmux 让会话在断线后继续运行。没有 tmux 时，普通 SSH 会话在连接断开时结束，正在跑的 Agent 也会被终止。
  • mosh 走 UDP，在 Wi-Fi 与蜂窝网络之间切换、手机换 IP 时终端不断线，弱网下输入也更跟手。

不需要手动安装：在 Roamtty 的主机菜单中选“安装插件”，应用会检测并用主机的包管理器安装（Linux 支持 apt、dnf、yum、pacman、zypper、apk、pkg，需 root 或 sudo；macOS 用 Homebrew 或 MacPorts，无需 sudo；Windows 用 winget 安装 psmux 作为 tmux 替代，无需管理员权限）。sudo 密码仅用于本次安装，不会保存。

mosh 使用服务器的 UDP 60000–61000 端口。经公网直连时，请在服务器防火墙和云服务商安全组中放行这段端口；通过 Tailscale 连接时一般不需要额外放行，见在 Roamtty 中使用。

添加主机

在主机页点 +，填写：

字段说明
名称显示用，例如“家里台式机”
地址 / IP域名、局域网 IP，或 Tailscale 分配的 100.x.y.z 地址 / MagicDNS 名称。不要带 ssh://、路径或空格
用户名、端口服务器上的登录账号；端口默认 22
认证方式密码；交互式认证（连接时显示服务器的问题，支持一次性验证码等多轮验证）；或 私钥（OpenSSH / PEM 格式的 Ed25519、RSA，支持加密私钥，文件不超过 256 KiB）

密码只在你勾选“在本机加密保存密码”后才保存，不勾选则每次连接时输入。导入的私钥加密保存在本机，私钥口令从不保存。保存主机时，应用会登录一次以识别远端系统并显示对应图标。

核对主机指纹

首次连接某个地址时，Roamtty 会显示服务器的 SHA-256 指纹，请与服务器上的真实指纹比对后再点信任。在服务器本机（或已经信任的终端）运行：

for f in /etc/ssh/ssh_host_*_key.pub; do ssh-keygen -lf "$f"; done

Windows 服务器的公钥位于 C:\ProgramData\ssh\，可在 PowerShell 中运行 ssh-keygen -lf C:\ProgramData\ssh\ssh_host_ed25519_key.pub。

之后若指纹变化，连接会被直接阻止。服务器重装或更换密钥时，请先确认新指纹，再在主机菜单中选“重新核验…”。

主机卡片与菜单

主机卡片显示系统图标、在线状态和建连延时。延时是最近一次成功探测中从开始 DNS 解析到 TCP 连接建立的时间，不含 SSH 登录；它是建连耗时，不是持续测量的会话往返时间，已有活跃会话时暂停探测。点卡片进入详情页查看实时监控；卡片右侧 ⋮ 菜单可选 AI Agent、打开终端、查看文件、安装插件、编辑或删除主机。删除主机会移除其配置与凭据，服务器上的 tmux 任务不受影响。

会话与 AI Agent

启动 AI Agent

  1. 点“AI Agent”，选择 Claude Code、Codex 或 Grok。
  2. 选择主机和起始文件夹（Agent 会在这个文件夹里工作）。
  3. 选择权限模式，应用会记住上次的选择：
    • 只读：Claude Code 以“计划”模式启动，先分析，批准计划后才开始修改；Codex 与 Grok 以只读沙箱启动（Grok 的 ~/.grok/ 状态目录和临时目录仍可写）。
    • 普通：修改文件或运行命令前先问你。
    • YOLO：跳过所有确认。只在你信任任务与环境时使用。

启动后仍可在 Agent 内部调整权限（例如 Claude Code 中按 Shift+Tab 切换模式，快捷键在小幽灵的快捷键环里）。“打开终端”则打开普通 shell，同样可以先选起始文件夹。

会话卡片

首页列出全部会话，每台主机最多 8 个。卡片以 Agent 当前的任务为标题（没有时显示 Agent 与文件夹），并显示状态：运行中（附正在执行的命令）、等待确认（Agent 在等你回答）或空闲（附上一轮耗时）。会话按“待确认”“运行中”“已完成”分组，顶部可以按状态筛选。等待确认的卡片上有“允许”按钮，不必打开终端即可批准 Agent 的操作；已完成的卡片显示回答摘要，点“追问”可以直接在卡片上输入下一条指令。为显示这些状态，应用会在服务器的 ~/.roamtty 下写入少量状态文件，可随时删除。

tmux 会话保持

服务器装有 tmux 时，每个会话都对应一个独立的远端 tmux 会话。锁屏、断网、切换网络或关闭应用后，任务继续在服务器上运行；断线的卡片会保留，点一下即重新登录并附着回原会话。

  • 卡片菜单中的“关闭”会结束远端 tmux 会话及其中的任务；未连接时会先重新登录再结束。
  • 如果服务器无法登录，长按卡片可强制删除：只移除手机上的卡片，远端 tmux 会话会继续保留。
  • 在终端里也可以用 tmux ls 查看 Roamtty 创建的会话。

mosh

主机装有 mosh 时，新会话的终端优先走 mosh（UDP），文件浏览与监控仍走 SSH。mosh 8 秒无回应时自动回退到 SSH，因此 UDP 被拦截也不影响使用，只是失去漫游能力。

小幽灵与操作栏

  • 点按屏幕边缘拿着扳手的小幽灵，展开操作栏：上传文件、下载文件、插入图片（最多 9 张，自动把远端路径填入终端，适合发给 Agent 看图）、常用命令（来自远端 shell 历史）和会话菜单（返回主机详情、关闭或重启会话、切换会话）。
  • 长按小幽灵，周围弹出当前程序的快捷键环（Claude Code、Codex、Grok、Gemini CLI 各有一套；普通 shell 为 Esc、Ctrl、Shift、Fn 等），拖到某个键上松手即发送；停在 Fn 上会展开 F1–F12。
  • 设置按钮中有“编辑文本”：先在编辑框里写好一段话（适合长提示词或多行文本），确认后再发送；发送文本与回车分开。
  • 停止输入后，光标行末尾会出现回车键，其余时间显示 Esc 键，方便回答 Agent 的确认或中断它。

终端字体可在设置中选择内置等宽字体或导入 .ttf / .otf 字体，内置 Nerd Font 图标回退。

文件

主机菜单中的“查看文件”通过 SFTP 浏览服务器文件：

  • 预览文本、代码（语法高亮）、Markdown 和图片；双击预览（图片为单击）切换全屏。较大的文本只显示开头 256 KiB，超过 8 MiB 的图片需下载后查看。
  • 重命名、删除、新建文件夹、复制路径，单个或多选批量下载，支持模糊搜索。
  • 文件浏览菜单可直接在当前文件夹打开终端或启动 AI Agent。
  • 在相册或其他 App 中把图片分享给 Roamtty，选择主机和会话后即可上传。

Android 下载到你选择的文件夹；iOS 下载的文件可在“文件”App 中找到。同名文件不会被覆盖。

主机监控

点主机卡片进入详情页，实时查看 CPU、内存、磁盘、网络、GPU 和占用最高的进程，适合确认 Agent 跑的测试或构建是否卡住。支持 Linux、macOS 和 Windows（Windows 使用系统自带的 PowerShell 5.1；装有 nvidia-smi 时显示 NVIDIA GPU）。

后台与锁屏

Android

Roamtty 在有活动连接时运行前台服务并显示通知（通知中可一键全部断开），最后一个连接断开即释放。锁屏后要保持 SSH 连接：

  1. 在 Roamtty 设置中打开“允许后台运行”，并允许不受电池优化限制。
  2. 部分国产系统（小米、华为、OPPO、vivo 等）还需在系统设置中允许 Roamtty 自启动、后台运行，并在最近任务中锁定。

iPhone

iOS 会在应用进入后台一段时间后暂停其网络连接，这是系统限制。用 tmux 会话即可：任务在服务器上继续运行，回到 Roamtty 时自动重新连接并附着。

无论哪个平台，真正保证任务不中断的是服务器上的 tmux，而不是手机一直在线。

从外网连接：Tailscale

服务器在家里或公司内网时，手机离开这个网络就连不上了。把 SSH 端口直接映射到公网并不安全，Tailscale 是更好的做法：它在你的设备之间建立基于 WireGuard 的加密虚拟局域网（tailnet），每台设备得到一个固定的 100.x.y.z 地址，手机无论在哪个网络都能像在局域网里一样访问服务器，服务器不需要公网 IP，也不需要开放任何入站端口。

Roamtty 不内置 Tailscale，也不需要任何特殊设置：在手机上安装 Tailscale 官方 App 并连上 tailnet，Roamtty 的流量就会经系统 VPN 走 Tailscale 隧道。

协调服务器Tailscale 官方或自建 Headscale
只交换公钥和地址，不经手流量
手机Roamtty
Tailscale App
⇄ WireGuard 直连打洞失败时 ↓ 经中继
服务器sshd · tmux · mosh
tailscaled
DERP 中继官方节点或自建，只转发加密数据，无法解密

两个角色要分清：

  • 协调服务器（控制面）负责登录、分配地址、分发各设备的公钥和访问策略。可以用 Tailscale 官方服务，也可以用开源实现 Headscale 自建。
  • DERP 中继在两台设备无法直接打洞（例如双方都在严格 NAT、运营商级 NAT 或公司防火墙后）时转发数据。数据始终是端到端加密的，中继看不到内容，但延迟取决于中继离你多远。

选择方案

方案适合需要
Tailscale 官方服务最快上手，个人使用免费额度足够Tailscale 账号；能访问 Tailscale 登录与协调服务器
官方服务 + 自建 DERP直连经常失败、官方中继延迟高（例如在中国大陆，官方没有大陆中继节点）一台离你近的、有公网 IP 的服务器
自建 Headscale + DERP不想依赖第三方账号，或官方服务访问不稳定一台有公网 IP 的 VPS 和一个域名

方案一：Tailscale 官方服务

  1. 服务器：Linux 运行 
    curl -fsSL https://tailscale.com/install.sh | sh
sudo tailscale up
    按提示在浏览器中打开链接登录。macOS、Windows 从 tailscale.com/download 安装客户端并登录。
  2. 手机：从 Google Play 或 App Store 安装 Tailscale，用同一个账号登录，按提示允许添加 VPN 配置。
  3. 在服务器上运行 tailscale ip -4 得到它的 100.x.y.z 地址（或在手机 Tailscale App 的设备列表中查看），在 Roamtty 中用这个地址添加主机。

建议在 Tailscale 管理后台对服务器关闭密钥过期（Disable key expiry），以免服务器每隔几个月需要重新登录，在外面时突然连不上。

方案二：自建 Headscale

Headscale 是 Tailscale 协调服务器的开源实现，手机和电脑仍使用 Tailscale 官方客户端，只是登录到你自己的服务器。下面以 Debian / Ubuntu VPS、域名 hs.example.com 为例。

1. 准备

  • 一台有公网 IP 的 VPS，建议离你常用的地方近（它通常也会兼任 DERP 中继）。
  • 域名 hs.example.com 解析到 VPS 的公网 IP。
  • 放行 TCP 80、443（HTTPS 与证书申请），以及 UDP 3478（若启用内置 DERP 的 STUN）。

2. 安装 Headscale

从 GitHub Releases 下载最新的 deb 包（写作时为 0.29.5）：

HEADSCALE_VERSION=0.29.5
HEADSCALE_ARCH=amd64   # ARM 服务器用 arm64
wget -O headscale.deb \
  "https://github.com/juanfont/headscale/releases/download/v${HEADSCALE_VERSION}/headscale_${HEADSCALE_VERSION}_linux_${HEADSCALE_ARCH}.deb"
sudo apt install ./headscale.deb

3. 修改配置

编辑 /etc/headscale/config.yaml，至少修改以下几项（完整示例在 /usr/share/doc/headscale/examples/config-example.yaml）：

# 客户端访问的地址，必须是 HTTPS
server_url: https://hs.example.com
# 只监听本机，由反向代理对外提供 HTTPS
listen_addr: 127.0.0.1:8080

prefixes:
  v4: 100.64.0.0/10
  v6: fd7a:115c:a1e0::/48

dns:
  magic_dns: true
  # tailnet 内的域名后缀，不能与 server_url 的域名相同或是其上级
  base_domain: ts.example.net

4. 配置 HTTPS 反向代理

反向代理必须支持 WebSocket 升级，Tailscale 客户端靠它与 Headscale 通信。最省事的是 Caddy，它会自动申请证书并处理升级。/etc/caddy/Caddyfile：

hs.example.com {
    reverse_proxy 127.0.0.1:8080
}

用 Nginx 时需设置 proxy_http_version 1.1、转发 Upgrade 和 Connection 头并关闭 proxy_buffering，参考 Headscale 反向代理文档。

sudo systemctl enable --now headscale
sudo systemctl reload caddy
sudo systemctl status headscale

5. 创建用户和预授权密钥

sudo headscale users create me
sudo headscale users list                         # 记下 me 的 ID
sudo headscale preauthkeys create --user 1 --reusable --expiration 24h

预授权密钥默认 1 小时内有效且只能用一次，加 --reusable 后可以给多台设备使用。密钥相当于入网凭据，用完后不要外传。

6. 服务器加入

在要被 Roamtty 连接的服务器上安装 Tailscale 客户端（同方案一第 1 步的安装脚本），然后：

sudo tailscale up --login-server https://hs.example.com --authkey <预授权密钥>

不想用预授权密钥时，去掉 --authkey，按提示打开浏览器页面，再在 VPS 上运行页面显示的注册命令（headscale auth register --user me --auth-id …）。

7. 手机加入

Android（Tailscale App）：

  1. 点右上角设置 → Accounts（账户）。
  2. 点右上角 ⋮ → Use an alternate server，输入 https://hs.example.com。如果弹出网页登录，可以关闭。
  3. 再次进入 Accounts → ⋮ → Use an auth key，粘贴预授权密钥；必要时在主界面点 Log in。

iPhone（Tailscale App）：

  1. 点右上角账户图标 → Log in…
  2. 点右上角选项菜单 → Use custom coordination server，输入 https://hs.example.com。
  3. 浏览器会打开注册页面，把页面上显示的命令复制到 VPS 上运行完成注册。

在 VPS 上运行 sudo headscale nodes list，应能看到服务器和手机两台设备及其 100.x 地址。

自建 DERP 中继

Tailscale 总会先尝试让两台设备直连，只有直连失败才走 DERP。默认的 DERP 节点由 Tailscale 官方提供，分布在海外；如果你所在地区离这些节点很远（例如中国大陆），走中继时延迟常在数百毫秒，终端打字会明显卡顿。在离你近的 VPS 上自建 DERP 就能解决。

方式 A：使用 Headscale 内置 DERP（推荐自建 Headscale 时使用）

在 /etc/headscale/config.yaml 中：

derp:
  server:
    enabled: true
    region_id: 999
    region_code: "headscale"
    region_name: "Headscale Embedded DERP"
    verify_clients: true          # 只允许本 tailnet 的设备使用
    stun_listen_addr: "0.0.0.0:3478"
    private_key_path: /var/lib/headscale/derp_server_private.key
    automatically_add_embedded_derp_region: true
    ipv4: 203.0.113.10            # VPS 的公网 IPv4
    # ipv6: 2001:db8::10          # 有公网 IPv6 时填写
  # 保留官方节点作为后备；改成 [] 则只使用自建节点
  urls:
    - https://controlplane.tailscale.com/derpmap/default
  paths: []

内置 DERP 复用 Headscale 的 HTTPS 端口（经上面的反向代理，路径 /derp），另外需要放行 UDP 3478。修改后 sudo systemctl restart headscale。

把 urls 设为 [] 会只剩你自己的一个中继，这台 VPS 出故障时所有需要中继的连接都会中断。确认自建节点工作正常后再决定是否去掉官方节点。

方式 B：独立运行 derper

想把中继放在另一台离你更近的服务器，或在使用 Tailscale 官方服务时自建中继，可以运行官方的 derper。在中继服务器上（需要 Go）：

go install tailscale.com/cmd/derper@latest
sudo ~/go/bin/derper -hostname derp.example.com -a :443 -stun-port 3478 \
  -certmode letsencrypt -verify-client-url https://hs.example.com/verify
  • -verify-client-url 让 derper 向 Headscale 校验来访设备，避免中继被陌生人使用。搭配 Tailscale 官方服务时，改为在中继服务器上安装并登录 Tailscale，再使用 -verify-clients。
  • 需放行 TCP 443（或你设置的端口）和 UDP 3478；letsencrypt 模式自动申请证书。
  • 建议用 systemd 托管 derper，保证重启后自动运行。

然后告诉协调服务器有这个中继。Headscale：新建 /etc/headscale/derp.yaml：

regions:
  900:
    regionid: 900
    regioncode: home
    regionname: My DERP
    nodes:
      - name: 900a
        regionid: 900
        hostname: derp.example.com
        ipv4: 203.0.113.20
        stunport: 3478
        stunonly: false
        derpport: 443

并在 config.yaml 的 derp.paths 中加入 /etc/headscale/derp.yaml，重启 Headscale。Tailscale 官方服务：在管理后台 Access controls 的策略文件中添加 derpMap，写法见 Tailscale 自定义 DERP 文档。

在中国大陆部署的注意事项

  • 境内云服务器上未备案的域名，通常无法在 80 / 443 端口提供 HTTPS 服务。可选择已备案的域名；或让 derper 监听非标准端口（如 -a :33445，并把 derpport 改成 33445），证书改用 DNS 验证方式（例如 acme.sh）申请，以 -certmode manual -certdir 指定，证书文件名需为 derp.example.com.crt 和 derp.example.com.key；也可以选择香港等地区的服务器。
  • 记得在云服务商的安全组中放行对应的 TCP 端口和 UDP 3478，安全组与系统防火墙是两层，缺一不可。

在 Roamtty 中使用

  • 主机地址填服务器的 Tailscale 地址 100.x.y.z，或 MagicDNS 名称（如 devbox.ts.example.net）。用 IP 最稳妥，不依赖手机上的 DNS 设置。
  • 先连 Tailscale，再开 Roamtty。Tailscale App 断开时，100.x 地址不可达，Roamtty 会提示“连接超时，请检查网络、VPN 和主机端口”。
  • 手机同一时间只能启用一个 VPN。Tailscale 运行时会占用系统 VPN 位置，其他 VPN 或代理类 App 会被断开，反之亦然。需要同时使用时，可以在 tailnet 中配置出口节点（exit node）代替。
  • mosh 可以直接在 Tailscale 上使用。Roamtty 的 mosh 会连到 SSH 实际连接的地址，也就是 100.x 地址，UDP 在隧道内传输，云安全组无需放行 60000–61000。若服务器启用了 ufw 等防火墙且拦截了 Tailscale 网卡，运行 sudo ufw allow in on tailscale0。
  • 使用服务器自己的 OpenSSH，不要开启 Tailscale SSH（tailscale up --ssh）。开启后 tailnet 内的 22 端口由 Tailscale 接管，主机指纹和认证方式都会变化。
  • 主机卡片上的延时沿实际隧道路径测量：直连时接近真实网络延迟，走 DERP 时包含中继绕行的时间。延时明显偏高时，先按下一节确认是否在走中继。
  • 服务器设置为开机自动启动 tailscaled（安装脚本默认已启用），并按方案一关闭密钥过期，避免远程时失联。

组网排查

命令（在服务器上运行）用途
tailscale status列出 tailnet 中的设备及在线状态，确认手机已连上
tailscale ping 手机的100.x地址显示是直连（via 1.2.3.4:41641）还是经中继（via DERP(xxx)）及往返时间
tailscale netcheck显示 NAT 类型、UDP 是否可用以及到各 DERP 节点的延迟，自建 DERP 应出现在列表中且延迟最低
sudo headscale nodes list（Headscale）查看已注册设备及最后在线时间

经常走中继时，可以在服务器所在网络的路由器上开启 UPnP，或为服务器放行 UDP 41641 入站，提高直连成功率。

提示原因与处理
连接超时，请检查网络、VPN 和主机端口地址或端口不对、服务器未开机、sshd 未运行，或 Tailscale 未连接。先在手机 Tailscale App 中确认已连接，再检查端口
