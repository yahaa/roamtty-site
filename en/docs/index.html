Documentation

For Roamtty on Android and iOS. Can't find an answer? See Support or email support@roamtty.com.

Roamtty is an SSH client. AI coding tools such as Claude Code, Codex and Grok run on your own server; Roamtty starts them from your phone, shows what they are doing and makes the terminal comfortable to use by touch. The app has no model and no backend server, and it connects only to the hosts you add.

Quick start

  1. Have a server you can SSH into, with the AI command-line tools you want installed and signed in. See Prepare the server.
  2. Make it reachable from your phone. On the same Wi-Fi you can use its LAN address. Away from home, we recommend a Tailscale network, so the server never has to be exposed to the internet.
  3. Tap + on the Hosts page to add it. Verify the fingerprint on first connection, then choose Install plugins in the host menu to add tmux and mosh.
  4. Tap AI Agent, pick the agent, host and starting folder, and get going. If you lock the phone, lose the network or close the app, the task keeps running in tmux on the server and Roamtty reattaches when you come back.

Prepare the server

Any Linux, macOS, BSD or Windows machine you can log in to over SSH will do: a desktop at home, a workstation at the office, a cloud VM or a Mac.

Install the AI command-line tools

Install the command-line version of Claude Code, Codex or Grok on the server following each tool's own instructions, and sign in once on the server (account or API key). Roamtty only starts them in the folder you pick; it never signs in for you and never handles your API keys. If claude, codex or grok starts in a plain SSH terminal, you are ready.

tmux and mosh (recommended)

  • tmux keeps sessions running after a disconnect. Without it, a plain SSH session ends when the connection drops, taking any running agent with it.
  • mosh runs over UDP, so the terminal survives switching between Wi-Fi and cellular or a change of IP address, and typing stays responsive on poor networks.

You don't need to install them by hand: choose Install plugins in the host menu and Roamtty detects them and installs them with the host's package manager (on Linux apt, dnf, yum, pacman, zypper, apk or pkg, which needs root or sudo; on macOS Homebrew or MacPorts, no sudo; on Windows psmux via winget as the tmux equivalent, no administrator rights). A sudo password is used for that install only and is never saved.

mosh uses UDP ports 60000–61000 on the server. Over the public internet, open that range in the server's firewall and your cloud provider's security group. Over Tailscale this is usually unnecessary; see Using it in Roamtty.

Add a host

Tap + on the Hosts page and fill in:

FieldNotes
NameFor display, such as “Home desktop”
Address / IPA domain name, a LAN IP, or the server's Tailscale 100.x.y.z address or MagicDNS name. No ssh://, path or spaces
Username, PortThe account on the server; the port defaults to 22
Authentication methodPassword; Interactive authentication (shows the server's prompts when connecting, including one-time codes and multi-step logins); or Private key (Ed25519 or RSA in OpenSSH or PEM format, encrypted keys supported, up to 256 KiB)

A password is saved only if you turn on “Encrypt and save password on this device”; otherwise you enter it each time. An imported private key is stored encrypted on the device; its passphrase is never saved. When you save the host, Roamtty logs in once to detect the remote system and show its icon.

Verify the host fingerprint

The first time you connect to an address, Roamtty shows the server's SHA-256 fingerprint. Compare it with the server's real fingerprint before trusting it. On the server itself (or from a terminal you already trust), run:

for f in /etc/ssh/ssh_host_*_key.pub; do ssh-keygen -lf "$f"; done

On Windows the keys live in C:\ProgramData\ssh\; in PowerShell run ssh-keygen -lf C:\ProgramData\ssh\ssh_host_ed25519_key.pub.

If the fingerprint changes later, the connection is blocked. After reinstalling the server or replacing its keys, confirm the new fingerprint and choose Verify again… in the host menu.

Host cards and menu

A host card shows the system icon, whether it is online and its connect latency: the time from starting DNS resolution to the TCP connection being established in the last successful check, without the SSH login. It measures connection setup, not the round-trip time of a running session, and checks pause while a session is active. Tap the card for live monitoring; the ⋮ menu on the right offers AI Agent, Open terminal, View files, Install plugins, Edit and Delete host. Deleting a host removes its settings and credentials and leaves tmux tasks on the server alone.

Sessions & AI agents

Start an AI agent

  1. Tap AI Agent and choose Claude Code, Codex or Grok.
  2. Pick the host and the starting folder the agent works in.
  3. Pick a permission mode; Roamtty remembers your last choice:
    • Read-only: Claude Code starts in Plan mode, analysing first and changing files only after you approve the plan; Codex and Grok start in a read-only sandbox (Grok can still write its state in ~/.grok/ and temporary directories).
    • Standard: asks before editing files or running commands.
    • YOLO: skips every confirmation. Use it only when you trust the task and the environment.

You can still change permissions inside the agent afterwards (for example Shift+Tab in Claude Code, available on the ghost's shortcut ring). Open terminal opens a plain shell and can also start in a chosen folder.

Session cards

The home page lists every session, up to 8 per host. A card is titled with the agent's current task (or the agent and folder) and shows its state: Running (with the command being run), Needs approval (the agent needs an answer) or Idle (with how long the last turn took). Sessions are grouped into needs you, running and done, with filters at the top. A card waiting for approval has an Allow button that approves the agent's step without opening the terminal; a finished card shows a summary of the answer, and Reply lets you type the next instruction on the card. To report these states the app writes a few small files under ~/.roamtty on the server, which you can delete at any time.

Persistent tmux sessions

With tmux on the server, each session has its own remote tmux session. Lock the phone, lose the network, switch networks or close the app and the task keeps running; the disconnected card stays, and tapping it logs in again and reattaches.

  • Close in the card menu ends the remote tmux session and everything in it, logging in first if needed.
  • If the server can't be reached, long-press the card to force delete it: only the card on your phone is removed and the remote tmux session is kept.
  • In a terminal, tmux ls lists the sessions Roamtty created.

mosh

When the host has mosh, new sessions carry the terminal over mosh (UDP), while file browsing and monitoring stay on SSH. If mosh doesn't answer within 8 seconds Roamtty falls back to SSH, so a blocked UDP port costs you roaming, not the session.

The ghost and the action bar

  • Tap the ghost holding a wrench at the screen edge to open the action bar: upload, download, insert images (up to 9, with their remote paths typed into the terminal, handy for showing an agent a screenshot), common commands (from the remote shell history) and the session menu (host details, close or restart the session, switch sessions).
  • Long-press the ghost for a ring of shortcuts for the program in front (Claude Code, Codex, Grok and Gemini CLI each have their own; a plain shell gets Esc, Ctrl, Shift, Fn and more). Drag onto a key and let go to send it; resting on Fn opens F1–F12.
  • Edit text in the settings button lets you compose a long prompt or several lines first and send it when you confirm; sending the text and Enter are separate.
  • When you stop typing an Enter key appears at the end of the cursor line, and an Esc key the rest of the time, for answering or interrupting an agent.

In Settings you can choose a built-in monospace font or import a .ttf / .otf font, with Nerd Font icon fallback.

Files

View files in the host menu explores the server over SFTP:

  • Preview text, code (syntax highlighted), Markdown and images; double-tap a preview (single tap for images) for full screen. Large text files show their first 256 KiB; images over 8 MiB need downloading.
  • Rename, delete, create folders, copy paths, and download one file or a multi-selection, with fuzzy search.
  • Open a terminal or start an AI agent in the current folder from the browser's menu.
  • Share images from Photos or another app to Roamtty, pick the host and session, and they are uploaded.

On Android files download to the folder you choose; on iOS they appear in the Files app. Existing files are never overwritten.

Host monitor

Tap a host card for live CPU, memory, disk, network, GPU and top processes, useful for checking whether an agent's tests or build are stuck. Works with Linux, macOS and Windows (Windows uses the built-in PowerShell 5.1; NVIDIA GPUs appear when nvidia-smi is installed).

Background & lock screen

Android

While a connection is open Roamtty runs a foreground service with a notification (which can disconnect everything at once) and releases it when the last connection closes. To keep SSH connected with the screen locked:

  1. Turn on Allow background activity in Roamtty's Settings and allow it to ignore battery optimisation.
  2. Some phones (Xiaomi, Huawei, OPPO, vivo and others) also need Roamtty allowed to auto-start and run in the background in system settings, and locked in Recents.

iPhone

iOS suspends an app's network connections a while after it goes to the background; that's a system limit. Use tmux sessions: the task keeps running on the server and Roamtty reconnects and reattaches when you return.

On either platform, what keeps a task alive is tmux on the server, not the phone staying online.

Remote access: Tailscale

When the server sits on a home or office network, your phone loses it the moment it leaves that network. Forwarding the SSH port to the internet is risky; Tailscale is a better approach. It builds an encrypted, WireGuard-based virtual network (a tailnet) between your devices. Each device gets a stable 100.x.y.z address, and your phone reaches the server from any network as if it were on the LAN, without a public IP on the server and without opening any inbound port.

Roamtty has no Tailscale built in and needs no special settings: install the official Tailscale app on your phone, connect it, and Roamtty's traffic goes through the Tailscale tunnel via the system VPN.

There are two separate roles:

  • The coordination server (control plane) handles sign-in, assigns addresses and distributes each device's public keys and access policy. Use Tailscale's service, or self-host the open-source Headscale.
  • DERP relays forward traffic when two devices can't connect directly, for example when both sit behind strict or carrier-grade NAT or a corporate firewall. Traffic stays end-to-end encrypted and the relay can't read it, but latency depends on how far away the relay is.

Option 1: Tailscale's service

  1. Server: on Linux run 
    curl -fsSL https://tailscale.com/install.sh | sh
sudo tailscale up
    and open the printed link to sign in. On macOS and Windows install the client from tailscale.com/download and sign in.
  2. Phone: install Tailscale from Google Play or the App Store, sign in with the same account and allow it to add a VPN configuration.
  3. Run tailscale ip -4 on the server to get its 100.x.y.z address (or find it in the phone app's device list) and add that address as a host in Roamtty.

In the Tailscale admin console, consider Disable key expiry for the server so it doesn't need signing in again every few months, which would otherwise cut you off while you are away.

Option 2: self-hosted Headscale

Headscale is an open-source implementation of Tailscale's coordination server. Phones and computers still use the official Tailscale clients, signing in to your server instead. The example below uses a Debian / Ubuntu VPS and the domain hs.example.com.

1. Prerequisites

  • A VPS with a public IP, ideally close to where you usually are (it often doubles as the DERP relay).
  • hs.example.com resolving to the VPS's public IP.
  • TCP 80 and 443 open (HTTPS and certificates), plus UDP 3478 if you enable the embedded DERP's STUN.

2. Install Headscale

Download the latest deb package from GitHub Releases (0.29.5 at the time of writing):

HEADSCALE_VERSION=0.29.5
HEADSCALE_ARCH=amd64   # arm64 on ARM servers
wget -O headscale.deb \
  "https://github.com/juanfont/headscale/releases/download/v${HEADSCALE_VERSION}/headscale_${HEADSCALE_VERSION}_linux_${HEADSCALE_ARCH}.deb"
sudo apt install ./headscale.deb

3. Configure

Edit /etc/headscale/config.yaml and change at least these keys (the full example is in /usr/share/doc/headscale/examples/config-example.yaml):

# The address clients use; must be HTTPS
server_url: https://hs.example.com
# Listen locally; the reverse proxy serves HTTPS
listen_addr: 127.0.0.1:8080

prefixes:
  v4: 100.64.0.0/10
  v6: fd7a:115c:a1e0::/48

dns:
  magic_dns: true
  # Domain suffix inside the tailnet; must not equal or contain server_url's domain
  base_domain: ts.example.net

4. Put HTTPS in front

The reverse proxy must support WebSocket upgrades; Tailscale clients depend on them to talk to Headscale. Caddy is the easiest: it obtains certificates and handles upgrades automatically. /etc/caddy/Caddyfile:

hs.example.com {
    reverse_proxy 127.0.0.1:8080
}

With Nginx, set proxy_http_version 1.1, pass the Upgrade and Connection headers and turn off proxy_buffering; see Headscale's reverse proxy guide.

sudo systemctl enable --now headscale
sudo systemctl reload caddy
sudo systemctl status headscale

5. Create a user and a pre-auth key

sudo headscale users create me
sudo headscale users list                         # note the ID of "me"
sudo headscale preauthkeys create --user 1 --reusable --expiration 24h

By default a pre-auth key is valid for one hour and works once; --reusable lets several devices use it. Treat the key as a credential for joining your network and don't share it.

6. Join the server

Install the Tailscale client on the server Roamtty will connect to (the install script from option 1, step 1), then:

sudo tailscale up --login-server https://hs.example.com --authkey <pre-auth key>

Without a pre-auth key, leave out --authkey, open the page it prints and run the registration command shown there on the VPS (headscale auth register --user me --auth-id …).

7. Join the phone

Android (Tailscale app):

  1. Tap the settings icon at the top right → Accounts.
  2. Tap ⋮ at the top right → Use an alternate server and enter https://hs.example.com. You can close a web sign-in page if one opens.
  3. Go back to Accounts → ⋮ → Use an auth key and paste the pre-auth key; tap Log in on the main screen if needed.

iPhone (Tailscale app):

  1. Tap the account icon at the top right → Log in…
  2. Tap the options menu at the top right → Use custom coordination server and enter https://hs.example.com.
  3. A registration page opens; run the command it shows on the VPS to finish.

sudo headscale nodes list on the VPS should now show both the server and the phone with their 100.x addresses.

Self-hosted DERP relays

Tailscale always tries a direct connection first and uses DERP only when that fails. The default DERP relays are run by Tailscale in a limited set of regions; if you are far from all of them (in mainland China, for example), relayed traffic often has several hundred milliseconds of latency and typing in the terminal feels sluggish. A relay on a VPS near you fixes that.

Option A: Headscale's embedded DERP (recommended with Headscale)

In /etc/headscale/config.yaml:

derp:
  server:
    enabled: true
    region_id: 999
    region_code: "headscale"
    region_name: "Headscale Embedded DERP"
    verify_clients: true          # only devices in this tailnet may use it
    stun_listen_addr: "0.0.0.0:3478"
    private_key_path: /var/lib/headscale/derp_server_private.key
    automatically_add_embedded_derp_region: true
    ipv4: 203.0.113.10            # the VPS's public IPv4
    # ipv6: 2001:db8::10          # if it has public IPv6
  # Keep Tailscale's relays as a fallback; set to [] to use only yours
  urls:
    - https://controlplane.tailscale.com/derpmap/default
  paths: []

The embedded relay shares Headscale's HTTPS port (through the reverse proxy above, at /derp) and also needs UDP 3478 open. Run sudo systemctl restart headscale afterwards.

Setting urls to [] leaves your single relay as the only one, so if that VPS fails every relayed connection fails with it. Make sure your relay works before removing Tailscale's.

Option B: a standalone derper

To put the relay on a different server closer to you, or to add your own relay to Tailscale's service, run Tailscale's derper. On the relay server (Go required):

go install tailscale.com/cmd/derper@latest
sudo ~/go/bin/derper -hostname derp.example.com -a :443 -stun-port 3478 \
  -certmode letsencrypt -verify-client-url https://hs.example.com/verify
  • -verify-client-url has derper check visitors with Headscale so strangers can't use your relay. With Tailscale's service, install and sign in to Tailscale on the relay server and use -verify-clients instead.
  • Open TCP 443 (or your chosen port) and UDP 3478; letsencrypt mode obtains the certificate automatically.
  • Run derper under systemd so it comes back after a reboot.

Then tell the coordination server about it. Headscale: create /etc/headscale/derp.yaml:

regions:
  900:
    regionid: 900
    regioncode: home
    regionname: My DERP
    nodes:
      - name: 900a
        regionid: 900
        hostname: derp.example.com
        ipv4: 203.0.113.20
        stunport: 3478
        stunonly: false
        derpport: 443

add /etc/headscale/derp.yaml to derp.paths in config.yaml and restart Headscale. Tailscale's service: add a derpMap to the policy file under Access controls in the admin console; see Tailscale's custom DERP guide.

Notes for mainland China

  • Cloud servers in mainland China usually can't serve HTTPS on ports 80 / 443 for a domain without ICP filing. Use a filed domain; or have derper listen on a non-standard port (such as -a :33445, with derpport set to 33445) and obtain the certificate through a DNS challenge (with acme.sh, for example), passing it with -certmode manual -certdir as files named derp.example.com.crt and derp.example.com.key; or use a server in Hong Kong or a nearby region.
  • Open the TCP port and UDP 3478 in your cloud provider's security group as well as the system firewall; both layers apply.

Using it in Roamtty

  • For the host address, use the server's Tailscale address 100.x.y.z or its MagicDNS name (such as devbox.ts.example.net). The IP is the most reliable since it doesn't depend on the phone's DNS settings.
  • Connect Tailscale first, then open Roamtty. With the Tailscale app disconnected, 100.x addresses are unreachable and Roamtty reports “Connection timed out. Check the network, VPN, and host port.”
  • A phone runs one VPN at a time. Tailscale takes the system VPN slot, so other VPN or proxy apps disconnect, and vice versa. If you need both, consider an exit node in your tailnet instead.
  • mosh works over Tailscale as is. Roamtty's mosh connects to the address SSH actually reached, which is the 100.x address, so UDP travels inside the tunnel and the cloud security group doesn't need 60000–61000 open. If a firewall such as ufw on the server blocks the Tailscale interface, run sudo ufw allow in on tailscale0.
  • Use the server's own OpenSSH and leave Tailscale SSH off (tailscale up --ssh). With it on, Tailscale takes over port 22 inside the tailnet and the host fingerprint and authentication change.
  • The latency on a host card is measured along the actual tunnel path: close to real network latency when direct, including the detour when relayed. If it looks high, check whether you are relayed (next section).
  • Make sure tailscaled starts at boot on the server (the install script enables it) and disable key expiry as in option 1, so you don't lose access while away.

Diagnosing the tailnet

Command (on the server)Purpose
tailscale statusLists tailnet devices and whether they are online; check the phone is there
tailscale ping <phone's 100.x address>Shows whether the path is direct (via 1.2.3.4:41641) or relayed (via DERP(xxx)), with the round-trip time
tailscale netcheckShows the NAT type, whether UDP works and the latency to each DERP relay; your own relay should be listed and closest
sudo headscale nodes list(Headscale) Registered devices and when they were last seen

If you are often relayed, turning on UPnP on the router in front of the server, or allowing inbound UDP 41641 to it, improves the odds of a direct connection.
