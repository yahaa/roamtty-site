Documentation

For Roamtty on Android and iOS. Something missing? See the support page or email roamtty@gmail.com.

Roamtty is an SSH client. AI coding tools (Claude Code, Codex, Grok and others) run on your own server; Roamtty starts them from your phone, shows what they are doing and makes the terminal easy to use by touch. There is no Roamtty backend: connections go only to the hosts you add.

Quick start

  1. Enable SSH on your server, then install the AI command-line tool and sign in to it.
  2. In Roamtty, tap + on the Hosts page to add the server, then choose Install plugins from its menu to get tmux and mosh.
  3. Tap AI Agent, pick a folder and start working. Locking the phone or losing signal doesn't stop the task; Roamtty reattaches when you come back.

Away from the server's network? Use Tailscale instead of exposing SSH to the internet.

Prepare a server

Any Linux, macOS, BSD or Windows machine you can SSH into will do.

  • Ubuntu / Debian: sudo apt install openssh-server
  • macOS: System Settings → General → Sharing → turn on Remote Login
  • Windows: add “OpenSSH Server” under Optional features, then run Start-Service sshd in an administrator PowerShell

Install claude, codex or grok following its own instructions and sign in once on the server. Roamtty never handles your account or API key.

No need to install tmux (keeps tasks running when you disconnect) or mosh (survives network changes) by hand: choose Install plugins from the host menu and Roamtty installs them with the host's package manager (sudo on Linux, never stored; Homebrew on macOS; psmux via winget on Windows).

Add a host

Tap + on the Hosts page and fill in a name, the address (domain, LAN IP or Tailscale 100.x.y.z), username and port.

Sign in with a Password, a Private key (Ed25519 / RSA, encrypted keys supported) or Interactive authentication (one-time codes and similar). A password is stored only if you turn on “Encrypt and save password on this device”. Leave the session mode on tmux.

Check the fingerprint on first connect. Run this on the server and compare with the SHA-256 fingerprint Roamtty shows before trusting it:

for f in /etc/ssh/ssh_host_*_key.pub; do ssh-keygen -lf "$f"; done

If the fingerprint later changes, the connection is blocked. Once you've confirmed the server was reinstalled or rekeyed, choose “Verify again…” from the host menu.

Start an AI agent

Tap AI Agent (also in the host menu), then pick a starting folder, the agent and a permission mode:

  • Plan / Read-only: Claude Code plans first and edits only after you approve; Codex and Grok run in a read-only sandbox.
  • Standard: asks before editing files or running commands.
  • YOLO: runs everything without asking. Use it only when you trust the task and the machine.

Your last choices are remembered and recent folders appear at the top. Open terminal starts a plain shell instead.

Sessions

The home page groups every session into Needs you, Running and Done, titled with the agent's current task.

  • Tap Allow on a card that needs you to approve without opening the terminal.
  • Done cards show a summary of the answer; tap Reply to send the next instruction right there.
  • Each session is its own tmux session on the server. Lock the phone, lose signal or close the app and the task keeps running; tap the card to reattach.
  • Close in the card menu ends the remote task. If the server is unreachable, long-press to force delete, which removes only the card on your phone.

With mosh installed the terminal prefers mosh (UDP) and falls back to SSH after 8 seconds without a reply.

Files and monitoring

View files in the host menu browses the server over SFTP: preview code, Markdown and images, rename, delete, download several files at once, or start an AI agent in the current folder. Share images to Roamtty from your gallery to upload them.

Tap a host card for live CPU, memory, disk, network, GPU and top processes, handy for checking whether a build or test run is stuck.

Background and lock screen

  • Android: turn on “Allow background activity” in Settings and exempt Roamtty from battery optimization. On Xiaomi, Huawei, OPPO, vivo and similar phones, also allow auto-start and lock the app in Recents.
  • iPhone: iOS pauses network connections in the background. The task keeps running in tmux on the server and Roamtty reconnects when you return.

What keeps a task alive is tmux on the server, not your phone staying online.

Connecting from anywhere: Tailscale

Tailscale puts your phone and server on one encrypted virtual network, each with a fixed 100.x.y.z address. The server needs no public IP and no open ports, and Roamtty needs no settings: its traffic goes through the system VPN.

  1. Server: on Linux run the commands below and sign in in the browser; on macOS or Windows install from tailscale.com/download. 
    curl -fsSL https://tailscale.com/install.sh | sh
sudo tailscale up
  2. Phone: install the Tailscale app and sign in with the same account.
  3. Add the server in Roamtty by its 100.x.y.z address (tailscale ip -4).
  • Connect Tailscale before opening Roamtty; a phone runs one VPN at a time.
  • mosh works inside the tunnel with no UDP ports to open.
  • Use the server's own OpenSSH and leave Tailscale SSH (--ssh) off, otherwise the host fingerprint changes.
  • Turn off key expiry for the server in the Tailscale admin console (Disable key expiry) so it doesn't drop off months later while you're away.
  • If latency is high, run tailscale ping <phone's 100.x address> on the server. via DERP means traffic is relayed; consider your own DERP relay (below).
Self-hosted Headscale (no Tailscale account)

Headscale is an open-source coordination server; phones and computers keep using the official Tailscale clients. You need a VPS with a public IP and a domain (hs.example.com below), with TCP 80 and 443 open.

# Install (see GitHub Releases; 0.29.5 at the time of writing)
wget -O headscale.deb https://github.com/juanfont/headscale/releases/download/v0.29.5/headscale_0.29.5_linux_amd64.deb
sudo apt install ./headscale.deb

Edit /etc/headscale/config.yaml:

server_url: https://hs.example.com
listen_addr: 127.0.0.1:8080
dns:
  magic_dns: true
  base_domain: ts.example.net   # must differ from the server_url domain

Serve HTTPS with Caddy (the proxy must pass WebSocket upgrades, which Caddy does by default), /etc/caddy/Caddyfile:

hs.example.com {
    reverse_proxy 127.0.0.1:8080
}
sudo systemctl enable --now headscale && sudo systemctl reload caddy
sudo headscale users create me
sudo headscale preauthkeys create --user 1 --reusable --expiration 24h

Join the devices:

  • Server: sudo tailscale up --login-server https://hs.example.com --authkey <key>
  • Android: Tailscale settings → Accounts → ⋮ → Use an alternate server, enter https://hs.example.com; then ⋮ → Use an auth key and paste the key.
  • iPhone: Log in… → options menu → Use custom coordination server, enter the address, then run the registration command shown on the page on the VPS.

When sudo headscale nodes list shows both devices, you're done.

Your own DERP relay (when direct connections fail or lag)

When two devices can't connect directly, traffic goes through a DERP relay (still end-to-end encrypted). If Tailscale's relays are far away, typing can lag by hundreds of milliseconds. With Headscale, the simplest fix is its embedded DERP, in config.yaml:

derp:
  server:
    enabled: true
    region_id: 999
    region_code: "headscale"
    region_name: "Headscale Embedded DERP"
    verify_clients: true
    stun_listen_addr: "0.0.0.0:3478"
    private_key_path: /var/lib/headscale/derp_server_private.key
    automatically_add_embedded_derp_region: true
    ipv4: 203.0.113.10          # the VPS's public IP
  urls:
    - https://controlplane.tailscale.com/derpmap/default   # keep official relays as a fallback
  paths: []

Open UDP 3478 and restart Headscale; tailscale netcheck on the server should list your relay with the lowest latency.

With Tailscale's own service, run the official derper on another server and add a derpMap to your policy file; see Tailscale's custom DERP guide. Open the ports in both the cloud security group and the server firewall.

Common errors

MessageWhat to do
Connection timed outCheck the address, port and that sshd is running, and that Tailscale is connected on the phone
Authentication failedCheck the username, password or key; for keys, the public key must be in the server's ~/.ssh/authorized_keys
The host fingerprint changedThe server was reinstalled, rekeyed or has Tailscale SSH on, or someone is intercepting the connection. Confirm the new fingerprint, then “Verify again…”
Neither tmux nor psmux was foundInstall it with Install plugins in the host menu
Each host can keep up to 8 sessionsClose sessions you no longer need on that host
The agent isn't signed in or isn't foundCheck in a plain terminal, as the same user, that claude / codex / grok runs and is signed in
